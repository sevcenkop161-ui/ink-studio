# Техническое задание — INK STUDIO
### Premium Tattoo Studio Website

---

## 1. Общая информация

- **Название проекта:** Ink Studio
- **Тип проекта:** коммерческий демонстрационный сайт тату-студии
- **Статус:** demo/concept project для портфолио разработчика
- **Цель:** создать современный, визуально дорогой и технически качественный сайт тату-студии, который демонстрирует навыки frontend/full-stack разработки, UI/UX, анимаций, работы с базой данных и интеграций.

Сайт должен выглядеть так, будто его можно передать реальной тату-студии после небольшой адаптации контента.

### Главная идея

Сайт не должен восприниматься как обычный шаблон:
«Название → текст → несколько картинок → контакты».

Он должен создавать ощущение бренда и студии.

Пользователь должен пройти путь:
увидел работу → заинтересовался стилем → познакомился с мастером → понял услуги → захотел записаться → оставил заявку.

---

## 2. Целевая аудитория

**Основная аудитория:**
- люди примерно 18–40 лет;
- люди, которые хотят сделать первую или следующую татуировку;
- пользователи, которые ценят эстетику, качество и индивидуальный подход;
- пользователи смартфонов;
- потенциальные клиенты тату-мастеров.

**Вторичная аудитория:**
- владельцы тату-студий;
- индивидуальные тату-мастера;
- пирсинг-мастера.

Последняя группа особенно важна для портфолио: сайт должен демонстрировать потенциальному заказчику, что подобное решение можно адаптировать под его бизнес.

---

## 3. Главная бизнес-задача

Сайт должен решать четыре основные задачи:

1. **Презентовать бренд** — показать атмосферу и стиль студии.
2. **Продемонстрировать работы** — пользователь должен легко посмотреть портфолио мастеров.
3. **Повысить доверие** — через фотографии, информацию о мастерах, опыт, отзывы, FAQ, аккуратный дизайн, понятную информацию об услугах.
4. **Получить заявку**

**Основной CTA сайта:** «Записаться»

**Вторичные CTA:**
- «Смотреть работы»
- «Наши мастера»

**Основной шрифт:** Inter или другой современный grotesk sans-serif.

Для крупных editorial-заголовков можно использовать дополнительный serif-шрифт, если это улучшает визуальную концепцию.

**Важно:**
- крупные заголовки;
- хороший line-height;
- много воздуха;
- четкая визуальная иерархия.

Первый экран должен производить впечатление сразу.

### Содержимое

- **Логотип:** INK STUDIO
- **Eyebrow:** TATTOO STUDIO / BERLIN
- **Главный заголовок:** Your story, inked forever.
  - Русская альтернативная версия: Искусство, которое остаётся с вами.
- **Подзаголовок:** короткое описание студии.
- **CTA:** Записаться
- **Вторичная кнопка:** Смотреть работы

### Визуал

Использовать большое качественное изображение или видео. Предпочтительно:
- крупный editorial visual;
- затемнение;
- мягкий gradient;
- легкое движение;
- cinematic atmosphere.

### Анимация

При загрузке появляются последовательно: фон → логотип → заголовок → описание → CTA.

Анимации должны быть плавными. Не использовать чрезмерные эффекты.

## 13. Portfolio / Works

Один из самых важных разделов. Главная задача: продать качество работ через визуал.

**Использовать:**
- masonry/grid;
- большие изображения;
- hover effects;
- плавное открытие изображения.

**Фильтры:** All / Blackwork / Fine Line / Realism / Minimal / Color

**При открытии работы:** большое изображение, стиль, мастер, краткое описание.

## 14. Services

Создать раздел услуг:

1. **Tattoo** — индивидуальные татуировки разных стилей.
2. **Piercing** — профессиональный пирсинг.
3. **Consultation** — консультация перед процедурой.

Каждая услуга: название, описание, ориентировочная стоимость, продолжительность, CTA.

Не использовать медицинские обещания.

## 15. Booking

Ключевая функциональная часть проекта. Пользователь нажимает «Записаться» → открывается форма.

- **Шаг 1** — выбор услуги: Tattoo / Piercing / Consultation
- **Шаг 2** — выбор мастера
- **Шаг 3** — выбор даты
- **Шаг 4** — выбор доступного времени
- **Шаг 5** — контактные данные: имя, Telegram, телефон, комментарий
- **Шаг 6** — подтверждение: пользователь видит дату, время, мастера, услугу и кнопку «Подтвердить запись»

## 24. Анимации

Использовать Motion / Framer Motion. Анимации должны улучшать UX.

**Использовать:** fade, slide, scale, stagger, image reveal, hover, page transitions.

**Не использовать:** бесконечные вращения, чрезмерный parallax, тяжелые эффекты, анимации, мешающие чтению.

Добавить поддержку `prefers-reduced-motion`.

Главный CTA должен повторяться в логичных местах. Не использовать слишком много разных кнопок.

## 29. Performance

Цель: сайт должен ощущаться быстрым.

**Использовать:** оптимизацию изображений, lazy loading, правильное разделение компонентов, минимизацию JavaScript, оптимальные размеры изображений.

Не добавлять библиотеку без необходимости.

## 30. Accessibility

Обязательно: keyboard navigation, aria-label там, где требуется, достаточный контраст, focus states, alt, семантические элементы, доступные формы.

## 31. Безопасность

Не хранить секреты в frontend. Использовать `.env`. Никогда не помещать секретные ключи непосредственно в код.

Проверять пользовательский ввод. Использовать server-side проверки там, где необходимо.

## 34. Требования к коду

Код должен быть: понятным, типизированным, компонентным, переиспользуемым, без огромных компонентов, без дублирования, без ненужных библиотек.

---

## 35. Работа с заказчиком как с новичком

Это очень важно. Заказчик использует Claude Code не только для создания проекта, но и для обучения.

**Поэтому:**
- Не делать всё молча.
- Перед каждым крупным этапом объяснять:
  - Что мы сейчас делаем.
  - Зачем это нужно.
  - Какие файлы будем создавать/изменять.
  - Как это работает.
  - Что важно понять.
- Если используется незнакомая технология: объяснить простыми словами, показать роль технологии в проекте, объяснить альтернативы.

Не нужно объяснять каждую строку простейшего CSS, но все архитектурные решения объяснять обязательно.

## Главный принцип проекта

Не стремиться сделать максимально много функций. Стремиться сделать небольшой, цельный, визуально сильный и технически качественный продукт.

Лучше 10 функций, которые действительно работают и хорошо выглядят, чем 30 недоделанных функций.

Проект должен быть достаточно качественным, чтобы после его завершения его можно было показать потенциальному клиенту со словами:

> «Вот пример решения, которое я могу адаптировать под ваш бизнес».
